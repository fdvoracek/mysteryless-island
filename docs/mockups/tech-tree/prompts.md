# Generation prompts

## 01 · compact branches

Use case: ui-mockup.
Create ONE polished high-fidelity desktop UI concept image for Mysteryless Island, a minimalist text survival game. This is a visual design proposal, not an implementation screenshot. Wide landscape artboard, approximately 1600 by 1000. Crisp, readable typography; refined serif item names, restrained functional UI, precise spacing. No fantasy illustrations, scenery, characters, skeuomorphic parchment, glow, chunky cards, or decorative clutter.
Shared chrome: a small "mysteryless island" wordmark, then tabs "area", "crafting", "building", with crafting selected. Dedicate almost all the remaining image to the tech tree itself; omit inventory, journal, stats and browser chrome. Small search control and unobtrusive navigation controls as appropriate.
Primary design goal: very low information density PER NODE, but support a large total number of nodes. Nodes show ONLY a short item name, optionally one tiny state mark, and a thin integrated progress fill for one node. Never put costs, time, prerequisite lists, repeated state words, large buttons, or details links inside every node. Connections and grouping do the explanatory work. Locked labels must remain readable. Use a mix of completed nodes, available nodes and future locked nodes, distinguished with line style and small marks, not color alone. One small global state legend is enough.
Show a single elegant floating hover tooltip adjacent to the fishing spear node with exact text: "fishing spear"; "10 firewood"; "needs something sharp"; "30 min with knife"; "click to craft". A small pointer indicates the hovered node. This is the only place item details appear.
Keep these current dependencies clear and accurate: rock knife is a root; it directly unlocks axe, fishing spear and rope independently; axe unlocks hoe. Other displayed recipes are illustrative future content for stress-testing scale, not new gameplay promises. Use categories tools, weapons, materials and containers, and around 25–35 visible compact nodes with room or navigation for more. Candidate future names include hammer, adze, pickaxe, sickle, saw, iron knife, iron axe, bow, arrows, sling, fishing rod, iron spear, fishing line, cloth, leather, basket, clay pot, clay jar, water flask, woven bag, bone needle and torch. Do not duplicate labels. Keep item text lowercase.
Footer in tiny unobtrusive type: "layout study · future recipes illustrative".
The result should feel like a beautiful, realistic, usable game interface screenshot, not a written presentation explaining UI principles.
Design direction 01: COMPACT VERTICAL BRANCHES. White background, black ink and soft gray connectors; classic literary game aesthetic. Small artboard heading "01 · compact branches". Place a single compact rock knife root at top, then a clean top-to-bottom dependency graph organized into four narrow category columns with category headings tools, weapons, materials, containers. All nodes are slim, restrained rectangular name chips, roughly 120 by 32, not large cards. Tool nodes descend within their lane; rock knife links across lanes to fishing spear and rope. Plenty of deliberate breathing room between groups, precise 1px orthogonal connectors routed behind chips, no tangled crossing web. Make the connections easy to follow even across categories. Completed nodes use a tiny check mark; available chips have a stronger outline; locked chips have a light dashed outline and readable charcoal names. Rope has a 40% progress fill across the bottom of its chip. A subtle bottom fade and vertical scrollbar suggest many more tiers below. The spear tooltip sits in spare canvas space, never covering the root or major connections. Balanced, calm composition with about 28 compact nodes. No numbered tiers in every node.
